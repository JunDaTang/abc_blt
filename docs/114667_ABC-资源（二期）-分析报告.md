## 四、与原始 Oracle 代码的对比分析

### 4.1 架构差异

| 维度 | 一期（Oracle） | 二期（BDP/Hive） |
|------|---------------|-----------------|
| **计算引擎** | Oracle 存储过程 | Hive/Spark SQL + ETL 调度 |
| **数据源** | 单一 `ODS_SUBJ_ACCO` | 多源：SAP BW、FCM、SAP 资产/设备、CO-PA、线下上传 |
| **表数量** | 约 4 张核心表 | **30+ 张 Hive 表** + 对等 Oracle 回写表 |
| **资源维度** | 5 个资源代码，一级映射 | **100+ 资源代码**，8种规则优先级匹配 |
| **航班关联** | 无 | FCM 费用需匹配到具体航班 |
| **管理账调整** | 无 | SAP 总账需正负翻转、科目重分类 |
| **资产折旧** | 无独立处理 | 完整的 SAP 资产链路 |
| **间接人工拆分** | 无 | 按多维度动因拆分 |
| **数据质量** | 无 | SAP vs FCM + 线上线下差异检查 |
| **数据同步** | 本地 Oracle | Oracle ↔ Hive 双向 ETL（9个 O→H + 12个 H→O） |

### 4.3 Oracle→Hive 迁移适配

| 改造项 | Oracle | Hive |
|--------|--------|------|
| 数据类型 | NUMBER/VARCHAR2/DATE | DECIMAL/STRING/STRING |
| 函数 | NVL/TO_CHAR/DECODE/ROWNUM | NVL/DATE_FORMAT/CASE WHEN/ROW_NUMBER() |
| 分区 | 无（按 month_code 过滤） | inc_month 按月分区 |
| 事务 | BEGIN/ROLLBACK/COMMIT | 幂等设计，失败重跑 |
| 调度 | 手动或 DBMS_SCHEDULE | BDP 工作流 + 依赖关系 |

## 五、关键发现

### 5.1 复杂度分布

- **最复杂节点**：`114325 资源基表_SAP`（V033），8 种规则类型优先级匹配
- **最宽表**：FCM 出账基表（58列）、预提基表（51列）
- **最多步骤**：`113700 资源基表_FCM`（V034），9 个 INSERT 步骤

### 5.2 资源归集核心演进

从一期"科目→资源"简单映射，演进为：
- **多源合并**：SAP + FCM + 资产折旧 + 线下上传
- **规则引擎化**：8种规则按优先级匹配
- **航班维度引入**：FCM 费用匹配到具体航班
- **间接人工动因拆分**：基于站坪占比、散航占比等多维度分配

### 5.3 潜在风险点

1. **硬编码分区日期**：`115923`/`131635` 中 UPLOAD 分区固定为 `201812`
2. **春节延迟硬编码**：`121908` 中 2025 年 2 月取 10 号分区的特殊逻辑
3. **湿租航班过期**：`113700` 中湿租限制在 `201901-202206`，已过期仍保留
4. **内部订单硬编码**：`113700` 中特定内部订单的硬编码替换（如 `102494396` → `102490311`）

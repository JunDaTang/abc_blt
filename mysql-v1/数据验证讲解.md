## 第 1 步：RR — 资源 → 资源（共享资源分摊到功能中心）

### 1.1 RR 解决什么问题？

有些成本记在"公共功能中心"（func_code=5010，运营公共），但它实际被收件(1010)和派件(1020)使用。RR 把它分下去。

### 1.2 RR 规则配置

```sql
SELECT fm_func_code, to_func_code, driv_code FROM abc_rel_rr_dist;
```

```
5010(公共运营) → 1010(收件)  动因=RR002(收派票数)
5010(公共运营) → 1020(派件)  动因=RR002(收派票数)
```

> 规则含义：公共运营中心的设备折旧(ZY0201)，按收派票数分给收件和派件功能中心。

### 1.3 RR 动因（各网点收派票数）

```sql
SELECT dept_code, func_code, qty FROM abc_fct_rr_driv ORDER BY dept_code, func_code;
```

| 网点 | 收件(1010) | 派件(1020) |
|------|-----------|-----------|
| 010AB 北京西城 | 391 | 419 |
| 010AC 北京朝阳 | 394 | 407 |
| 020AB 广州天河 | 401 | 382 |
| 020AC 广州越秀 | 401 | 387 |
| 021AB 上海浦东 | 388 | 392 |
| 021AC 上海嘉定 | 369 | 376 |
| 755AB 深圳南山 | 387 | 371 |
| 755AC 深圳福田 | 388 | 385 |
| **合计** | **3,119** | **3,119** |

> 每个网点处理了多少票，就分摊多少共享成本。这就是 README 中"RR002 = 收派票数"的实际数据。

### 1.4 RR 分摊结果

| 1010 收件 | RR002 | 24,569.94 |

> 5010 功能中心的 49,144.66 元设备折旧，按各网点的收派票数，分给了收件(1010)和派件(1020)。

## 第 2 步：RA — 资源 → 作业（部门资源分给各项作业）

### 2.1 RA 规则（前 10 条）

```sql

FROM abc_rel_ra_dist LIMIT 10;
```

| 源功能中心 | 资源 | 目标功能中心 | 目标作业 | 动因 |
|-----------|------|------------|---------|------|
| 1010 收件 | ZY0101 | 1010 | 101010 收件操作 | RA001 直接归属 |
| 1020 派件 | ZY0101 | 1020 | 101020 派件操作 | RA001 直接归属 |
| 1030 运输 | ZY0301 | 1030 | 201000 支线 | RA002 线路里程 |
| 1030 运输 | ZY0301 | 1030 | 202000 干线 | RA002 线路里程 |

> 关键区别：

> - **RA002**（线路里程）：按运输里程比例分给干线/支线
> - **RA003**（装卸票数）：按操作票数×系数分给装卸/中转

## 第 3 步：AA — 作业 → 作业（辅助作业间分摊）

### 3.1 AA 的核心：装载重量拆分

AA 用动因 AA002 把运输成本拆成**正常装载**和**闲置容量**：

```sql
SELECT SUBSTRING(fm_acti_code, 5, 2) AS cargo_type,
       ROUND(SUM(to_amt), 2) AS allocated
FROM abc_fct_aa_dist
WHERE driv_code = 'AA002'
GROUP BY SUBSTRING(fm_acti_code, 5, 2);
```

| 类型 | 金额 | 说明 |
|------|------|------|
| 10 正常装载 | (大部分) | 实际载货的成本 |
| 20 闲置容量 | (小部分) | 空载浪费的成本 |

> 代码逻辑：车辆载重上限 3000kg，实际载重 2000kg → 正常 2000kg，闲置 1000kg。
> 这样管理层能看到"有多少钱花在了运空气上"。

### 3.2 AA 其他动因

```sql
SELECT driv_code, COUNT(*) AS cnt, ROUND(SUM(to_amt), 2) AS total
FROM abc_fct_aa_dist
GROUP BY driv_code;
```

| 动因 | 含义 |
|------|------|
| AA002 | 按装载重量拆分正常/闲置 |
| AA003 | 按整包/单件拆分装卸成本 |
| AA004 | 按整包/单件拆分中转成本 |

## 第 4 步：AO — 作业 → 运单（最终分到每个包裹）

### 4.1 AO 是按什么分到运单的？

AO 动因决定了每个运单分摊多少成本：

| 动因代码 | 含义 | 度量 |
|---------|------|------|
| AO002 | 收件运单 | 每单=1 |
| AO003 | 派件运单 | 每单=1 |
| AO005 | 运输运单 | **运单重量(kg)** |
| AO006 | 整包装卸 | 每单=1 |
| AO007 | 单件装卸 | 每单=1 |

> 关键：干线运输按**重量**分，不是按次数！50kg 的包裹比 1kg 的包裹分摊更多运输成本。

## 关键验证点

### 1. 成本守恒

```sql
-- 资源清单总额 = AO分摊总额
SELECT '资源清单' AS src, ROUND(SUM(amt), 2) AS total FROM abc_fct_reso_list
UNION ALL
SELECT 'AO分摊', ROUND(SUM(to_amt), 2) FROM abc_fct_ao_dist WHERE to_amt IS NOT NULL;
```

两者应该相等 = **197,878.78**。

### 2. 分摊检测（5 步平衡检查）

```sql
-- 运行检测程序
CALL p_abc_fct_check_dist('2019-06-01');
SELECT * FROM abc_fct_chk_dist;
```

检测 5 个维度：理论应摊、实际已摊、未分摊、重复分摊——确保每一级分摊都没问题。

### 3. rn=1 避免收入重复

```sql
-- 同一个运单在 AO 中有多条记录（被多个作业分摊）
-- 但 rn=1 只有一条，确保收入只计一次
SELECT waybill_no, COUNT(*) AS cnt,
       SUM(CASE WHEN rn = 1 THEN income_amt ELSE 0 END) AS revenue
FROM abc_bsl_cost_base
GROUP BY waybill_no HAVING cnt > 1
LIMIT 5;
```

## 四、与原始 Oracle 代码的对比分析

### 4.1 四级分摊的对应关系

| Oracle 四级分摊 | Oracle 存储过程 | Hive 节点 | 说明 |
|----------------|----------------|-----------|------|
| RR分摊 | 7.2-RR分摊程序.prc | **无对应节点** | 二期不含RR，RR在一期(任务134190)中处理 |
| RA分摊 | 7.2-RA分摊程序.prc | 114705 | 资源→作业中心 |
| AA分摊 | 7.2-AA分摊程序.prc | 114701 | 作业间分摊 |
| AO分摊 | 8.2-AO分摊程序.prc | 114702 | **命名变化：AO→AS** |

### 4.2 数据模型简化（最核心变化）

**Oracle 一期（多维度）：**
- 维度：`dept_code`（部门）、`func_code`（功能）、`reso_code`（资源）、`car_no`（车号）
- 四级分摊：RR → RA → AA → AO
- AO 输出包含 `waybill_no`（运单号）

**Hive 二期（简化，航空业务聚焦）：**
- 维度：`cost_code`（成本中心）、`reso_code`（资源）、`fly_no`（飞机号）、`intern_code`（内部订单）、`cb_type_code`（成本属性）
- 三级分摊：RA → AA → AS
- AS 输出包含 `flight_id`（航班ID）

**关键差异：**
1. **去掉RR分摊**：RR在独立任务中处理，RA 直接从资源结果表取数据
2. **去掉部门/功能维度**：直接用 `cost_code` 关联，无需 `abc_dim_dept`
3. **车号→飞机号**：`car_no` → `fly_no`
4. **运单→航班**：`waybill_no` → `flight_id`

### 4.3 分摊核心逻辑对比（以RA为例）

**Oracle RA：**
```
tmp01: abc_dim_dept x abc_rel_ra_dist → 分摊标准（含部门维度JOIN）
tmp02: abc_fct_rr_dist UNION ALL abc_fct_reso_list → 合并资源
tmp03: tmp01 LEFT JOIN tmp02 → 关联资源
tmp04: tmp03 LEFT JOIN abc_fct_ra_driv → 关联动因 + 窗口函数求总量
结果: INSERT INTO abc_fct_ra_dist
```

**Hive RA（114705）：**
```
tmp01: air_abc_rel_ra_dist → 分摊标准（无维度表JOIN）
tmp02: air_abc_fact_reso_list LEFT JOIN 规则 → 生成资源（含内部订单逻辑）
tmp03: tmp01 LEFT JOIN tmp02 → 关联资源
tmp04: air_abc_fact_ra_driv → 生成动因
tmp05: tmp03 LEFT JOIN tmp04 → 关联动因 + 窗口函数（含复杂CASE匹配）
结果: INSERT OVERWRITE ... PARTITION
```

**关键差异：**
1. 去掉维度表关联，直接用 `cost_code`
2. 新增 `intern_code`、`fly_no`、`cb_type_code` 维度
3. 动因匹配更复杂（RA006/RA009 用拼接键解决多资源对应）
4. **核心公式一致**：`fm_reso_amt * (driv_qty / total_driv_qty)`
5. **直接计入判断一致**：`driv_code in ('RA001', 'AA001', 'AS001')` 时直接计入

### 4.4 Oracle→Hive 迁移适配

| 改造项 | Oracle | Hive |
|--------|--------|------|
| 存储结构 | PL/SQL + 永久临时表(delete+insert) | HiveQL + 临时表(drop+create as parquet) |
| 分区管理 | 按 month_code 过滤 | INSERT OVERWRITE PARTITION (inc_month, hq_dist_code) |
| 事务处理 | BEGIN/EXCEPTION/ROLLBACK/COMMIT | 无事务，幂等设计 |
| 变量传递 | PL/SQL 变量 | Hive 参数 `${v_month}` |
| 数据同步 | 无（Oracle 内完成） | 6个 ETL(H→O) 节点同步回 Oracle |
| 命名规范 | AO (activity-order) | AS (activity-shipment/航班) |
| 数据精度 | Oracle NUMBER | Hive DOUBLE + ROUND(x, 4/6) |
| 时间函数 | `sysdate` | `from_unixtime(unix_timestamp(), ...)` |

### 4.5 质量保障机制

**Oracle（一期）：** 2个检测程序

**Hive（二期）：** 4个检测/校验节点，完整数据质量闭环：
- RA/AA/AO 分摊检测：5步校验（总资源→理论发送方→实际发送方→已分摊→未分摊→重复分摊）
- 分摊规则检查：7类规则校验 + 4级未分摊明细 + AS金额变化校验

## 五、关键发现

1. **AO→AS 命名变更**：AO 改为 AS（Activity Shipment/航班），反映业务从运单维度到航班维度的转变。

2. **去掉RR级分摊**：Oracle 四级(RR→RA→AA→AO) → Hive 三级(RA→AA→AS)。RR被拆分到独立上游任务。

3. **新增成本属性维度**：`cb_type_code` 贯穿三级分摊全流程，Oracle 原始版本无此字段。

4. **动因匹配高度复杂**：大量 CASE WHEN 处理特殊匹配（RA006/RA009 用资源+成本中心拼接键，航前航后用 substr 截取匹配），是二期新增的适配规则。

5. **幂等设计**：所有节点采用 `drop + create as parquet + insert overwrite` 模式，天然支持失败重跑。

6. **Hive→Oracle 双向架构**：分摊在 Hive 完成，6个 ETL 节点将结果同步回 Oracle（`fin_abc` 库），下游报表仍依赖 Oracle。

7. **B73N机型改造（V017最新变更）**：宽表节点(119406)在2025年1月新增3个方案机型字段（`mp_ac_type_b/t/7`），支持 B73N（737 MAX）机型改造。
